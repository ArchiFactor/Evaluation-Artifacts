How to run the test suite:
- The suite is only green on Linux. On Windows exactly 45 tests fail on hard-coded "\n" vs CRLF and Path-separator assertions (14 in common, 31 in webapp). Those are pre-existing platform artifacts, not your breakage. Run the tests in Docker (Docker Desktop is already running).
- Your edits are uncommitted and the runner builds from a clone, which carries committed state only. The command below therefore first exports your working-tree changes to wip.patch, and the script re-applies that patch inside the container. Always run it as the single chained command below so the patch is never stale.
- If you create any NEW (untracked) file, run `git add -N .` in /d/scripts/box__mojito before the command above, or the patch will not carry it.
- Run the command below in the FOREGROUND and wait for it to finish: the full reactor takes about 12 minutes and your Bash timeout allows 30, so it completes in a single call. It writes the full log to run.log (read it for any failure details) and prints the result summary at the end.
- If you ever need to watch a long-running background command, use the Monitor tool with an until-loop that checks every 20 seconds (e.g. `until grep -q "Reactor Summary" run.log; do sleep 20; done`), so the wait happens inside one call.
- Expected green baseline: 2013 tests, 0 failures, 0 errors, 96 skipped.
